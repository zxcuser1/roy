# Лабораторная работа №4 — SSA для 2D/3D планирования маршрутов БПЛА

Реализация на **C# / ASP.NET Core (.NET 10)**. Интерфейс открывается в браузере, работает без внешних JS-библиотек и без NuGet-зависимостей. При наличии SDK интернет для сборки проекта не требуется.

## Запуск

Требуется **.NET SDK 10.x**.

```bash
# Windows PowerShell, Ubuntu или macOS — из папки проекта
cd SSA_Lab4_NET10
dotnet restore
dotnet run
```

Быстрый запуск: `./start.sh` в Linux/macOS или двойной щелчок по `start.bat` в Windows.

Откройте **http://127.0.0.1:5084**. Не закрывайте консоль, пока работает программа. При повторном запуске другой копии возможен конфликт порта 5084.

**Если у вас только .NET SDK 9:** откройте `SSA_Lab4.csproj` и замените `<TargetFramework>net10.0</TargetFramework>` на `net9.0`. В проекте не используются API, уникальные для .NET 10; сборка для .NET 9 предусмотрена на уровне исходников, но не была проверена фактическим компилятором.

### Автоматическая проверка

```bash
dotnet run -- --self-test
```

Тест проверяет число препятствий, координаты целей, строит маршруты во всех пяти сценариях с уменьшенными параметрами SSA, затем проверяет препятствия и временные столкновения. Ошибка приводит к ненулевому завершению.

### Сборка для конкретной ОС

```bash
# Linux x64
dotnet publish -c Release -r linux-x64 --self-contained true -p:PublishSingleFile=true

# Windows x64
dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true

# macOS Apple Silicon
dotnet publish -c Release -r osx-arm64 --self-contained true -p:PublishSingleFile=true
```

Папка результата: `bin/Release/net10.0/<RID>/publish/`. Папку `wwwroot` также нужно сохранить рядом с исполняемым файлом. При `--self-contained true` соответствующие runtime packs могут потребовать предварительного скачивания; для исходного запуска достаточно установленного SDK.

Все габариты препятствий и пары старт/цель скопированы из таблиц 2 и 3 исходного PDF. Координаты заданы в `Core/MapFactory.cs`.

### Ошибка в данных карты 4

В таблице 2 **второй БПЛА** стартует из `(3,2,5)`, но препятствие №2 в таблице 3 занимает `(0,0,0)–(5,6,10)`. Старт находится **внутри препятствия**, и безопасный маршрут из него при заданной геометрии невозможен.

Поэтому включена видимая опция **«Корректировать старт внутри препятствия»**. При запуске выполняется перенос к ближайшей из проверяемых свободных точек за гранью препятствия; программа выводит предупреждение с исходными и новыми координатами. В оригинальной карте и таблице программы координаты сохраняются без изменения. Коррекцию можно выключить: тогда БПЛА №2 будет помечен как не имеющий допустимого пути.

## Алгоритм и отличия от методички

1. **A*** строит начальный допустимый путь на сетке: 2D шаг `0.25`, карты 1–3 шаг `0.5`, карта 4 шаг `0.7`. Он упрощается проверкой прямой видимости (не пересекает препятствия). Это вспомогательная эвристика, которой нет в описанном в PDF базовом SSA.
2. **SSA** кодирует `N` промежуточных точек в вектор координат. Начальное решение A* включено в популяцию; остальные решения генерируются случайно. Лидер ориентируется на лучшее найденное решение, последователи обновляются по формуле усреднения.
3. Коэффициент `c1 = 2·exp(-(4·l/L)²)` — стандартная формула SSA. Для выбора знака обновления лидера используется `c3 >= 0.5`, а не `c3 >= 0` из PDF, так как при `c3 ∈ [0,1]` порог `0` сделал бы вторую ветвь недостижимой.
4. **Функция стоимости**: `C = длина пути + 1.6 × число поворотов(>35°) + 10000 × число недопустимых сегментов + 10000 × число точек за границей`. Конечная точка маршрута всегда закреплена в `G`, поэтому `C_gap = 0`. Коэффициенты выбраны для демонстрации; их нет в методичке.
5. Дополнительно используется небольшая **локальная мутация лучшего решения** (гибридная эвристика) — она не входит в базовый SSA.
6. **Квинтическая интерполяция** для сглаживания и повторная полная проверка столкновений. При невозможности безопасно сгладить маршрут используется исходный ломаный путь.
7. **Предотвращение столкновений между БПЛА**: сначала каждый маршрут строится независимо, затем подбираются задержки старта. Для каждой пары движущихся по сегментам БПЛА вычисляется минимальная дистанция при их одновременном полёте с постоянной скоростью. До старта БПЛА отсутствует в сцене, при прибытии исчезает. Минимальная дистанция настраивается; в крайнем случае запуск нового БПЛА переносится до завершения предыдущих.

**Ограничения:** алгоритм оптимизирует пути *с гибридной A*-инициализацией*, а не «чистым SSA». Нельзя считать полученные метрики независимым сравнением SSA с A*. При неудачном поиске безопасный маршрут не подменяется фиктивным «успехом»: выводится предупреждение. Модель не учитывает динамику, ограничение ускорения, реальные габариты и непрерывное присутствие ещё не запущенных БПЛА.

## Пользовательский интерфейс

- Выберите 2D или одну из четырёх 3D-карт.
- Настройте популяцию, число итераций, seed, скорость, минимальную дистанцию, сглаживание.
- Нажмите **«Выполнить оптимизацию»**.
- Маршруты после SSA показаны цветными линиями; переключатель «Показать A*» показывает исходный путь штриховой линией.
- В 3D: ЛКМ + движение мыши — поворот камеры, колесо — масштаб.
- «Пуск» анимирует движение с постоянной скоростью, регулятор времени позволяет проматывать сцену. По прибытии агент исчезает.
- Справа внизу отображаются стоимости/длины/задержки; отдельно график сходимости каждого маршрута.
- Кнопка **CSV** экспортирует таблицу результата для отчёта.

## API

- `GET /api/maps` — список доступных карт.
- `GET /api/map/0` ... `/api/map/4` — исходные координаты карт.
- `POST /api/run` — запускает SSA.

Пример:

```bash
curl -s -X POST http://127.0.0.1:5084/api/run \
  -H 'Content-Type: application/json' \
  -d '{"mapId":2,"population":55,"iterations":130,"seed":42,"speed":2,"separation":0.4,"smooth":true,"repairInvalidStarts":true}' \
  > result.json
```
