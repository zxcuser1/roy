# Лабораторная работа № 3 — потенциальные поля и рой БПЛА

**Технологии:** C# 12 / .NET 9, ASP.NET Core Minimal API, HTML5 Canvas, JavaScript. Без NuGet-пакетов и 3D-движков.

В проекте реализована учебная симуляция пяти БПЛА в трёхмерном пространстве с построением глобального маршрута и локальным обходом препятствий. Исходный материал — «Лабораторная 3. Алгоритм глобального планирования траектории для роя БПЛА в трехмерном пространстве на основе искусственных потенциальных полей» (13 страниц).

**Важно:** исходный материал — описание исследования, а не техническое задание с точными критериями сдачи. Реализована интерпретация его основных идей, а не дословная репликация исходного эксперимента.

## 1. Как запустить

Нужен **.NET SDK 9.0** (именно SDK, а не только Runtime):

```sh
dotnet --list-sdks
```

Перейти в каталог, где лежит `SwarmLab3.csproj`, и запустить:

```sh
dotnet restore
dotnet run
```

Открыть **http://localhost:5083** в любом современном браузере.

На Ubuntu, macOS и Windows команды одинаковые. Для завершения сервера нажать `Ctrl+C` в терминале. Для запуска из корня другой папки: `dotnet run --project ./SwarmLab3.csproj`.

### Проверки

```sh
dotnet run -- --self-test
```

Проверяются поиск маршрута для A* и Theta*–APF в трёх сценах, прямая видимость отрезков, отсутствие пересечений препятствий и дронов на протяжении 100 секунд моделируемого времени. При ошибках процесс завершится с ненулевым кодом. **Проверки включены в исходный код, но не были запущены в среде подготовки архива — там отсутствует .NET SDK.**

## 2. Управление

- Сцена: «Городские препятствия», «Узкий коридор», «Открытая площадка».
- Планировщик: `Theta*–APF` или обычный `A*`. При переключении полёт начинается сначала.
- **Пауза / Продолжить**, **Заново**, изменение скорости от 0,25× до 4×.
- Мышью можно вращать камеру; колесом — менять масштаб; кнопка «Вид сверху» устанавливает вертикальную камеру.
- Переключатели показывают оба маршрута, следы дронов и схематичный срез потенциального поля.
- Горячие клавиши: `Пробел` — пауза; `R` — перезапуск; `V` — вид сверху.

Справа отображается 3D-сцена, слева — время полёта и сравнение длины маршрута, числа поворотов, просмотренных узлов и времени планирования.

## 3. Как устроен алгоритм

### Глобальное планирование — A* и Theta*–APF

Карта имеет размер **80 × 80 × 12 м**, покрыта 3D-сеткой с шагом **1,5 м**. Из каждой воксельной точки можно перейти в 26 соседних направлений. Трёхмерное евклидово расстояние используется в `g(n)` и `h(n)`.

- **A*** исследует соседние воксели, проверяет пересечения прямых отрезков со стенами и выбирает узел с минимальным `g+h`.
- **Theta*** дополнительно проверяет, виден ли соседний узел из родителя текущего узла. Если да, путь строится напрямую, без промежуточного излома.
- В варианте **Theta*–APF** добавлен **небольшой положительный штраф отталкивающего потенциала** для выбора узлов дальше от препятствий. Он влияет на порядок поиска. `f(n) = g(n) + h(n) + 0.25 U_rep(n)`. Из-за этого добавления оптимальность пути математически не гарантируется.
- Для всех рёбер и сокращений Theta* проверяется **весь отрезок**, а не только концы. Радиус безопасности виртуального лидера при планировании — 1,10 м.

Это **3D-адаптация комбинированного метода**. Формула эвристики из подраздела 2.3 исходного PDF выписана для восьми соседей в 2D, поэтому непосредственно для 26 направлений не подходит. Здесь используется евклидова эвристика и отдельный потенциал препятствий; сравнивать полученные числа с табличными результатами статьи как точное воспроизведение нельзя.

### Виртуальный лидер

Виртуальный лидер проходит глобальный маршрут. Остальные пять дронов удерживают свои целевые смещения в локальной системе координат лидера (ось вперёд и поперечная ось). При подходе к препятствиям формация частично сжимается.

Скорость i-го дрона формируется по принципу из раздела 3.1:

```text
v_i,cmd = v_leader + k * (position_target_i - position_i)
           + F_obstacles + F_drones
```

Коэффициент `k = 1.35`. Скорость ограничена 5,4 м/с, ускорение — 11,5 м/с². Виртуальный лидер движется со скоростью до 3,1 м/с. БПЛА **не исчезают на финише**: поддержание формации после прибытия соответствует задаче этой лабораторной.

### Искусственные потенциальные поля (APF)

Для каждого препятствия и для каждого соседнего БПЛА действует отталкивание при `d < d0`:

```text
F_rep = μ * (1/d - 1/d0) / d² * direction_away
```

Силы складываются с управляющей командой скорости. Также действует отталкивание от границ мира. Комбинация двух независимых вкладов соответствует идее формул (26)–(31) PDF.

Для защиты от случайных проникновений в стены и от физического пересечения дронов **каждое новое положение дополнительно проверяется геометрически**. При запретном перемещении дрон пытается скользить вдоль доступных осей, иначе останавливается на этом шаге. Эта проверка нужна, потому что один только градиент APF не гарантирует отсутствия столкновений.

**Ограничения:** дроны моделируются как сферы, препятствия — как параллелепипеды; нет моделирования аэродинамики, инерции корпуса, задержек связи и реального автопилота. Потенциальное поле может создавать локальные минимумы, поэтому не гарантируется успех перестроения в любой произвольной карте. Реализовано учебное моделирование, не управление физическими БПЛА.

## 5. Как показать на защите

1. Запустить городскую сцену. Показать движение пяти БПЛА, виртуального лидера и объёмные препятствия.
2. Поставить на паузу, включить оба маршрута, сравнить длину, число поворотов и число обработанных узлов A* и Theta*–APF.
3. Переключиться на «Узкий коридор», показать изменение строя и высоты при обходе препятствия.
4. Включить отображение потенциального поля и объяснить, почему цель притягивает, а препятствия и другие дроны отталкивают.
5. Показать, что алгоритмы действительно трёхмерные: z координата учитывается в планировщике и движении.
6. Выполнить `dotnet run -- --self-test`, показать проверки целостности маршрутов и непересечения объектов.

**Примечание к метрикам:** в исходной статье A* сравнивается с Theta*–APF на 2D и 3D картах; в этой программе оба алгоритма используют одинаковую евклидову эвристику и проверку коллизий, поэтому результаты не обязаны иметь те же относительные величины, что в статье. Само время поиска зависит от CPU, SDK и условий запуска.

## 6. Публикация на других ОС

При наличии соответствующих runtime pack и доступа для восстановления зависимостей:

```sh
# Windows x64
dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -o publish/win-x64

# Ubuntu / Linux x64
dotnet publish -c Release -r linux-x64 --self-contained true -p:PublishSingleFile=true -o publish/linux-x64

# macOS Apple Silicon
dotnet publish -c Release -r osx-arm64 --self-contained true -p:PublishSingleFile=true -o publish/osx-arm64
```

Файлы `wwwroot` и `appsettings.json` должны находиться рядом с исполняемым файлом (стандартная публикация web-проекта их копирует). Файлы для одной ОС нельзя использовать как исполняемые на другой ОС; нужно собирать под нужный Runtime Identifier. После публикации приложение открывается в браузере на локальном компьютере. Для режима с установленным .NET Runtime используйте `dotnet publish -c Release` и `dotnet SwarmLab3.dll` из каталога публикации.

Чтобы перейти на **.NET 10**, замените `net9.0` на `net10.0` в `.csproj` и установите .NET SDK 10; исходный код не привязан к платформе.
